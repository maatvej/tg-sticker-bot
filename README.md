# Бот-конвертер стикеров Telegram

Присылаете боту стикер — он отвечает файлом:

| Стикер | Формат в Telegram | Что пришлёт бот | Другие форматы по кнопке |
|---|---|---|---|
| Обычный (статичный) | WEBP | PNG | WebP (исходный файл) |
| Анимированный | TGS (Lottie) | GIF | APNG, WebP, WebM |
| Видеостикер | WEBM (VP9) | GIF | APNG, WebP, WebM (исходный файл) |

Под каждым файлом есть кнопки с другими форматами: нажатие присылает тот же стикер в выбранном формате.
Прозрачность сохраняется. Файлы приходят документом: так Telegram не пережимает PNG в JPEG
и не перекодирует GIF в MP4.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте выданный токен.
2. Вставьте токен в файл `.env` вместо заглушки `PASTE_YOUR_BOT_TOKEN_FROM_BOTFATHER`.
3. Запустите бота:

   ```powershell
   .venv\Scripts\python -m sticker_bot
   ```

Виртуальное окружение `.venv` (Python 3.12) уже создано, зависимости установлены.
Ставить в систему ffmpeg или rlottie не нужно — они входят в pip-пакеты `imageio-ffmpeg` и `rlottie-python`.

Если api.telegram.org недоступен (пропала сеть, переподключается VPN), бот не падает — ни при запуске,
ни во время работы: он пишет в лог об ошибке сети и повторяет попытки, пока связь не вернётся.

### Установка с нуля (например, на сервере)

Windows:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env   # затем впишите токен в .env
.venv\Scripts\python -m sticker_bot
```

Linux / macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env          # затем впишите токен в .env
.venv/bin/python -m sticker_bot
```

## Настройки

Читаются из `.env`, переменные окружения имеют приоритет.

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен от @BotFather, обязательно |
| `MAX_CONCURRENT_CONVERSIONS` | сколько стикеров конвертировать одновременно, по умолчанию `2`; конвертация анимированного стикера занимает до ~250 МБ памяти |

## Тесты

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest
```

Тесты генерируют стикеры всех трёх типов на лету и прогоняют бота целиком
(апдейт → конвертация → ответ) с подменённым API Telegram, без сети.

## Форматы для анимированных стикеров

Замеры на четырёх реальных анимациях Telegram (512×512, 60 fps, 3 секунды):

| Формат | Кадры | Полупрозрачность | Качество | Размер | Время |
|---|---|---|---|---|---|
| GIF | до 50 в секунду | нет | 256 цветов в кадре | 3–5 МБ | 1–2 с |
| APNG | все | есть | без потерь | 7–17 МБ | 2–3 с |
| WebP | все | есть | с потерями, на глаз почти не заметными | 3–6 МБ | 2–3 с |
| WebM | все | есть | с потерями, цвет в половинном разрешении | ~1 МБ | 3–5 с |

- **GIF** открывается где угодно, поэтому бот присылает его по умолчанию. Его ограничения описаны ниже.
- **APNG** — единственный формат без потерь: если нужна максимальная точность, выбирайте его.
- **WebP** и **WebM** хранят цвет в половинном разрешении (4:2:0), поэтому тонкие цветные контуры
  чуть размываются. Для WebM с альфа-каналом это ограничение самого кодека VP9 — так устроены
  и видеостикеры Telegram.
- Видеостикер в WebM бот присылает как есть, без перекодирования.

## Как это работает

- Статичный стикер конвертирует Pillow.
- Кадры TGS рендерит rlottie (тот же движок, что в приложениях Telegram), кадры WEBM декодирует ffmpeg
  с декодером `libvpx-vp9`: встроенный декодер VP9 теряет альфа-канал, и фон получился бы чёрным.
- Из кадров GIF, WebP и WebM собирает ffmpeg, а APNG — Pillow: он записывает только изменившиеся
  области кадров и справляется в 8 раз быстрее ffmpeg.

### Ограничения формата GIF

- **Не больше 50 fps.** Задержка кадра в GIF хранится в сотых долях секунды, поэтому 60 fps можно
  записать только чередованием задержек 20 и 10 мс. Но браузеры (Chrome, Firefox, Safari) задержки
  до 10 мс включительно растягивают до 100 мс, и такой GIF играл бы в 2,8 раза медленнее. Поэтому
  анимации чаще 50 fps (у TGS обычно 60) пересэмплируются в 50 fps: каждый шестой кадр выпадает,
  а скорость и длительность сохраняются. Всё, что не быстрее 50 fps, остаётся как есть.
- **Не больше 256 цветов в кадре.** Бот строит одну палитру на всю анимацию и использует упорядоченный
  дизеринг: одинаковые пиксели соседних кадров кодируются одинаково, и неподвижные части стикера
  не мерцают. Палитра на каждый кадр передаёт цвета точнее, но на реальных стикерах заставляет мерцать
  до трети неподвижных пикселей.
- **Прозрачность только полная или никакая.** Пиксели прозрачнее 50% становятся прозрачными,
  остальные — непрозрачными, поэтому мягкие тени и сглаженные края теряют полупрозрачность.

Если важны все кадры или полупрозрачность, выберите APNG, WebP или WebM кнопкой под файлом.

В группах бот по умолчанию видит только команды и ответы на свои сообщения (privacy mode),
поэтому пользоваться им удобнее в личных сообщениях.

## Структура

```
sticker_bot/
  __main__.py    точка входа: настройки и запуск long polling
  config.py      настройки из .env
  handlers.py    обработчики сообщений
  converter.py   конвертация в PNG, GIF, APNG, WebP и WebM
tests/           тесты
```
